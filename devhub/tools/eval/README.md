# RAG 离线评测（P0 基建）

黄金评测集驱动的回归评测，任何检索/重排/切片参数调整后都应复跑一次，用数据判断优化是否有效（对标 RAGAS/TruLens 的轻量实现）。

## 文件

- `golden_set.json` —— 52 条用例（47 检索题 + 5 拒答题），每条含期望文档 + 期望关键词。**关键词已经过 SQL 逐条校验确实存在于活跃切片**（大小写敏感）。
- `eval_runner.py` —— 跑分脚本，调 `POST /api/v1/chat`，输出逐用例明细 + 汇总指标。
- `compare_eval.py` —— 对比两份报告的指标增减与用例恢复/退化。

## 用法

```bash
# 1. 清缓存（保证冷启动一致，语义缓存/检索缓存都会影响结果）
docker exec agent-redis sh -c "redis-cli --scan --pattern 'agent:rag:*' | xargs -r redis-cli DEL"

# 2. 跑分（label 用于报告命名）
python eval_runner.py <label> --show   # --show 额外打印未达标用例

# 3. 对比
python compare_eval.py baseline improved
```

## 指标口径

| 指标 | 含义 |
|---|---|
| kwRecall@5 | 期望关键词在 top5 来源切片中的覆盖率（内容层召回） |
| MRR | 首个相关切片排名倒数均值（排序质量） |
| docHit@5 / top1Acc | 期望文档进入 top5 / 排第一的比率 |
| grounded | 答案文本包含至少一个期望关键词（有据可依） |
| correctMiss | 知识库外问题的正确拒答率 |
| latency | 端到端耗时 |

## 基线 → 两阶段架构（2026-10-15）

架构改动：每通道召回 topK×2 → **25**；RRF 融合截 topK → **15 候选**；重排内部截 3 → **全量排序，编排层截 top-k=5**（QAnything 两阶段职责划分）。
同时修复评测抓出的 bug：关键词/exact 通道未按文档生命周期过滤，superseded 旧版本切片挤占 top-k。

| 指标 | baseline | improved | Δ |
|---|---|---|---|
| kwRecall@5 | 0.851 | **0.968** | +0.117 |
| MRR | 0.791 | **0.833** | +0.042 |
| docHit@5 | 0.979 | **1.000** | +0.021 |
| correctMiss | 0.0* | **0.8** | （*基线实测 4/5，初版标记词漏判"暂无"） |
| avgLatency | 19.4s | 20.8s | +1.4s |

7 个弱召回用例全部恢复（jm-09/13/20/21、ar-02、co-01、sc-03），零退化。

## 防幻觉三道防线（2026-10-15，antihall2 轮）

新增：①CRAG 检索质量门控（重排 top1<0.5 拒答）②逐句引用标注 [n] + 无据内容剥离（带反馈重生成一次）③RAGAS 式忠实度校验（评测同步返回/生产异步落库 message.faith_score，同步 <0.4 改判拒答）。前端 [n] 上标可点击定位来源。

| 指标 | improved | antihall2 | Δ |
|---|---|---|---|
| correctMiss | 0.8 | **1.0** | +0.2 |
| grounded | 0.915 | **0.957** | +0.042 |
| faithfulness（新增） | — | **0.933** | |
| kwRecall@5 | 0.968 | 0.926 | -0.042 |
| MRR | 0.833 | 0.78 | -0.053 |
| avgLatency | 20.8s | 24.5s | +3.7s |

说明：
- kwRecall/MRR 的回落来自 LLM 重排的运行间波动（ar-01/ar-10 两例换了个 chunk 选择，docHit 仍 1.0），非防线误伤；重排是 LLM 调用，单轮对比存在天然噪声。想消除波动可切 `AGENT_RAG_RERANK_PROVIDER=zhipu`（确定性 cross-encoder）。
- 忠实度兜底的实战案例：miss-04（Python GIL）曾逃过门控被模型自由发挥作答，忠实度校验判 0.0 分当场识别——现已加"同步忠实度<0.4 自动改判拒答"兜底。
- 剥离器带内容重叠预检（句子关键词在资料中出现≥30% 则保留），避免误删"thread -b"这类漏标但有据的关键句。

## Advanced 层级借鉴轮（2026-10-16，含一次诚实回滚）

借鉴 LlamaIndex/LangChain 四项：Parent-Child 切片检索、历史指代消解改写、HyDE、Lost-in-the-Middle 摆位。评测集扩至 57 题（+5 多轮追问题，runner 支持 setup 会话）。

| 指标 | antihall2 基线 | pclevel(子块200) | final2(回滚后) |
|---|---|---|---|
| kwRecall@5 | 0.926 | 0.788 | 0.846 |
| MRR | 0.780 | 0.707 | 0.677 |
| docHit@5 | 1.000 | 0.846 | 0.942 |

**结论与教训（按验收纪律执行）**：
- **Parent-Child 回滚**（代码保留，`child-size` 调小启用）：两个实测坑——①父块进重排会被打低分误触 CRAG 门控（修复：先重排子块后展开父块）；②关键词通道搜 200 字子块时 BM25 词频区分度崩塌（"COLA"类核心词处处命中），修复为父块粒度后仍净退化 0.08 → 配置回滚
- **HyDE 默认关闭**（`hyde-enabled: false`）：flash 生成的假设文档向量对 complex 题召回不稳，疑似残余退化主因之一；待换用高质量模型生成假设文档后专项验证
- **指代消解保留**：多轮用例 2/5 完全通过（"那它应该怎么正确使用？"→正确检索 ThreadLocal 内容），零额外成本（搭改写便车）
- **Lost-in-the-Middle 摆位保留**：不影响检索指标，生成侧标准做法
- 附带发现：COLA 的分层详情是**外链图片**，文本库不含该信息——历史"答对"实为模型补全的轻度幻觉，现被引用纪律正确拦截（评测集已修正该用例）

本轮净结论：**Advanced 层级并非所有"标准技术"都适用于当前数据形态，评测纪律避免了一次带伤上线的"优化"**。

## 已知遗留（P1 方向）

- `faithfulness 0.933` 的低分用例（jm-05/07/16、co-01/03）多为校验器对"合理改述"偏严，可观察后再调 prompt
- 表格解析（PDF 表格丢失）仍是检索质量天花板，属 P1-4
- 评测口径依赖关键词精确匹配，中英文混排文档可能有少量误差（AIR 用例曾因 MySQL LIKE 大小写不敏感误校验，已用 BINARY 复核）
